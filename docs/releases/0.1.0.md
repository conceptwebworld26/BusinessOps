# BusinessOps 0.1.0 — release notes

**Status: release candidate.** Version `0.1.0` (`.claude-plugin/plugin.json`). The proposed tag is `v0.1.0`. BusinessOps
0.1.0 is **not released** until the owner pushes, tags and publishes it. Until then, this page describes the candidate
checkpointed locally on `main`.

> **Lineage (2026-09-30).** This candidate was prepared under the product's previous name, BusinessIQ, and was carried
> into BusinessOps unchanged in function. BusinessOps Milestone 1 migrated its identifiers (`businessiq` →
> `businessops`, `biq` → `bops`); this page names them in their current form. The validation results, smoke tests and
> commit checkpoints described below were recorded under the BusinessIQ identifiers in the BusinessIQ repository, and
> have not been re-run as BusinessOps except where `project_plan.md` says so. The new BusinessOps repository has no
> commits yet.

BusinessOps is a Claude Code plugin for decision support. It analyses your own business data locally, researches public
sources through a privacy gate, and combines the two into evidenced analysis. Every figure comes from a deterministic
engine, and every claim carries its provenance, confidence and limitations.

## What 0.1.0 contains

18 user-facing commands, 16 skills and 2 subagents. See the [Command Reference](../commands/README.md) and the
[Skill Reference](../skills/README.md).

- **Internal business analytics.** These commands read one local `.xlsx`, `.xlsm`, `.csv` or `.tsv` file, and never
  modify it:
  - `/business-health`, `/sales-analysis`, `/customer-analysis`, `/product-analysis`;
  - `/profitability-analysis`, `/cash-flow-analysis`;
  - `/ask-business-data`, which routes one question to an existing metric.
  - Excel is read through four tiers: an existing `openpyxl`, a consented isolated runtime, a standard-library
    parser, or a CSV export.
- **The KPI engine.** 28 KPIs, each reported as computed, unavailable (naming the missing field) or not applicable to
  the business model. A data-quality gate halts the run on a `CRITICAL` grade.
- **Forecasting.** `/revenue-forecast`:
  - five candidate methods are backtested on held-out history, and the band is the measured error;
  - base, upside and downside scenarios, each with an assumption register;
  - no forecast below the configured minimum history (12 periods by default).
- **Anomaly detection.** `/anomaly-detection`:
  - periods are scored against their own trailing baseline, with materiality, and the contributors are listed;
  - it never assigns a cause, and never calls a deviation fraud.
- **External business research.** `/company-analysis`, `/market-analysis`, `/competitor-analysis` and
  `/industry-research`:
  - queries are built from public terms only and pass the disclosure gate;
  - the `bops-research-scout` subagent retrieves with web tools only, and has no file access;
  - its reply reaches the parser byte for byte, through a harness capture (ADR-0053);
  - sources are tiered and dated locally, figures are quoted and never estimated, and nothing is ranked;
  - all four passed fresh-session live smoke tests on 2026-09-27.
- **Your figure against a public benchmark.** `/benchmark-comparison`. Your figure never enters the query, and the join
  happens locally.
- **Cross-domain synthesis.** One strict synthesis set per analysis. It is built from your file and from public
  research, and every statement is grounded in evidence already in the set.
- **SWOT, strategy recommendations, decision support and executive reporting:**
  - `/swot-analysis`;
  - `/strategy-analysis`: class-7 recommendations with evidence, rationale, risks and derived confidence, unranked;
  - `/decision-support`: a draft twelve-part decision package;
  - `/executive-report`: a draft eleven-section report that assembles only what the analysis produced.
- **Business Context.** An optional `./.businessops/business_context.json`. It decides which KPIs apply, and supplies
  the currency and reporting conventions. With no context, relevance filtering is off, and the output says so.
- **Privacy and security:**
  - the four-tier disclosure model (ADR-0009);
  - every research-query fragment is screened against your workspace's business data (ADR-0050);
  - Tier 3 material (credentials, customer names, raw records) is refused outright;
  - no secrets are stored.
- **Write safety.** The write guard (ADR-0051):
  - once a session uses BusinessOps, consequential writes are blocked before they run unless you approve that exact
    operation (`approve BOPS-W-…`, single use, 10 minutes);
  - some operations have no approval path at all, such as changing original source data or rewriting git history;
  - read-only analysis needs no approval.
- **The local verifier.** `--final` on `/decision-support` and `/executive-report` finalises a draft only after a blind
  recomputation by the local `bops-verifier` MCP server. The server starts through the same interpreter resolver as the
  engine, so `python3`-only hosts work (ADR-0052).

**Requirements:**

- Claude Code;
- a POSIX shell;
- Python 3.9 or newer as `python` or `python3`, or set `BOPS_PYTHON`.

The engine uses the standard library only. Install instructions are in the [README](../../README.md#quick-start).

## Known limitations in 0.1.0

- **Connected business systems are not available.** The connector registry is empty by design, and reading records
  from connected systems is blocked. Export to a spreadsheet or CSV instead.
- **Milestone 9 is partly in progress, outside this release's scope.** The four research commands are complete and
  live-verified. The planned `bops-external-research` skill and three tier-test rows remain open.
- **Known model-behaviour limitations (M13-DEF-14, -15 and -16)**, accepted for 0.1.0:
  - the assistant sometimes asks for approval before read-only analysis;
  - it sometimes omits a required statement, such as a clarifying question or "no reliable source found";
  - a Tier-2 research query may be refused outright instead of being shown to you for approval.

  Each errs toward caution. See [`docs/testing/defects.md`](../testing/defects.md).
- **Always-on context cost** is about **7,260 tokens**, measured with `claude plugin details`. The project's
  self-imposed target is ≤ 3,000 tokens (ADR-0013). It is not met, and the target has not been changed.
- **Packaging.** The marketplace entry installs the whole repository, about 633 files and 9.7 MB, including development
  documentation, tests and evaluation material. This is accepted for 0.1.0. No secrets are tracked.
- **Other documented limits:**
  - forecasts are not carried into executive reports;
  - a large CSV is loaded whole, not streamed;
  - formulas are not evaluated (cached values are read);
  - five designed skills are not shipped (D-13; see the [Skill Reference](../skills/README.md));
  - research quality is bounded by what is publicly published.

  The full list is in [`README.md`](../../README.md#limitations) and [`architecture.md`](../../architecture.md) §20.
