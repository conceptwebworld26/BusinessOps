**Why no new decision is needed.** Each element of the definition follows from accepted text or established

| Session | One **fresh** Claude Code session per scenario, started by the owner, with the plugin loaded from this repository at a recorded commit | Repository precedent: the M9-D "owner-run fresh-session live smoke tests". The development session also holds the graders and expected properties in context |
| Working directory | An empty scratch directory outside the repository, with only the case's named inputs copied in | §F.6 (copy only) and ADR-0041 §5 (a case consumes only what it names). Running inside the repository would load the development `CLAUDE.md` and the graders |
| Restrictions | Synthetic data only; no web tool, no MCP tool, no authentication. The owner declines such requests and grants no consequential action | §E.1: "performed under the same restrictions as §F.2 to §F.4 and §F.11" |
| Case observed | One designated case per S3 row (table in `eval-suite.md`); the prompt verbatim; a single turn | §E.1: "the case the scenario stands in for" is singular. The eval runs the case's prompt as its single message |
| Record | `docs/testing/manual/<row>-<case-id>.md`, labelled `manual_observation`, carrying §E.1's four items plus provenance (date, commit, CLI version, model, input hashes, declined tools) and the real verbatim excerpts | §E.1's location, label and four items |
