## 8. Tests performed

The single authorised execution, run once from the repository root:

```
claude plugin eval . --case a01-read-only-anomaly-detection --runs 3 --threshold 1.0 \
  --no-publish --mocks record --ablation none --max-cost-usd 5 --trust-plugin \
  --allow-tools "Bash(python:*)" "Bash(python *)" \
  --json <scratchpad>/a01-result.json
```

`--runs 3 --threshold 1.0` is §F's requirement, `--no-publish` keeps results local, `--ablation none` is the
non-routing setting, `--max-cost-usd 5` is the owner's ceiling, and the two `--allow-tools` patterns are the
`engine-python` grant the cases declare.

Then the focused validation (section 9).

## 10. Issues discovered

**M13-DEF-05** — the M13.2 eval suite does not load in `claude plugin eval`: every case file is refused for a missing
`schema_version`. Recorded in `docs/testing/defects.md` (source `eval`, class `infrastructure`, status `open`,
`blocks_m13_completion: yes` by §G.1's rule) and in `project_plan.md`'s *Known issues*.

It is **M13's own infrastructure**, not product behaviour: the case files and the schema `biq-eval-case/1` are M13.2
artifacts, and no command, skill, agent or engine module is implicated. The repository schema was authored without a
platform reference — `docs/testing/eval-suite.md` has said since it was written that the schema is repository-local
and unverified against the harness — and this execution is the first evidence of what the harness actually requires.

It is **not fixed here**: the prompt authorised one attempt and forbade retrying or editing case files to make a
second attempt possible. §G.2 permits fixing an infrastructure defect within M13, under its own prompt.

**Still open, untouched by this task:** G-3 (the rest of the platform execution mechanics — grader mapping, the
`engine-python` grant, input delivery into the case sandbox — none of which this attempt could reach), V-4 (minimum
CLI version), the Unix runtime verification, and the twelve `manual_observation` scenarios.
