# 2026-09-16 — M10.2-R.14: the local join, internal analysis reaches strict synthesis

**Milestone:** M10.2-R.14 — make the internal half of the synthesis representation reachable
**Status on completion:** COMPLETED
**Supersedes:** None

---

## 1. Prompt / task performed

Make the internal half of the synthesis representation user-reachable, so a BusinessIQ flow
can compute an internal result from the existing command path, retrieve a public benchmark
through the existing retrieval path, keep the internal data local, put both into one strict
`SynthesisSet` through the existing translators and footing seam, and compare them locally.

Nineteen parts, of which the load-bearing ones were: inspect the existing translators before
changing anything; create the smallest sequencing seam; guarantee internal data stays local;
add one user-reachable surface; keep domain logic out of the seam; preserve ADR-0023 internal
footing; build the real production path; test that raw internal values never enter the
request; positive, negative and privacy tests; a command-level integration test; one new ADR;
minimal guidance and documentation; and leave protected components alone.

## 2. Objective

The roadmap review that preceded this milestone established the gap by inspection, not from
the plan's summary: `from_analysis_set()` and `from_kpi_result()` appear in `merge.py`,
`synthesis/__init__.py`, ADRs, development records, fixtures and tests — and **nowhere
else**. No skill, command or agent called them, and `commands/runner.py`, `pipeline.py` and
`render/` contain no reference to synthesis at all.

The consequence was concrete: ADR-0009's Decision and `architecture.md` §1/§7 both name the
local join as the **default** comparative behaviour covering "substantially all comparative
questions", and all four research skills promise it in their failure tables — and nothing
joined locally.

## 4. What the inspection found

**The objects already lined up.** `commands.run("profitability-analysis", source=<demo>)`
returns a genuine `CommandResult` carrying genuine `AnalysisSet` objects under `analyses` and
28 genuine `KPIResult` objects under `kpis` — exactly the types `from_analysis_set()` and
`from_kpi_result()` accept. Probing confirmed a translated internal statement lands as
`kind=CALCULATION`, `domain=internal`, `trust=internal`, `evidence_class=4`, with
`dimension_provenance=[]` (engine-footed, ADR-0023), and that a **strict** set does not null
internal dimensions — `resolve()`'s strict branch applies to `EXTERNAL` only. Nothing was
missing except the ordering and a surface.

**Layering decided where the seam goes.** The seam needs a `CommandResult`, which the command
layer owns. `synthesis/` sits below the command layer, and CLAUDE.md §2.3 forbids a layer
depending upward — so putting the seam in `synthesis/` would have inverted the dependency.
It lives in `commands/` instead, and the synthesis package still knows nothing about commands
(asserted by test).

**No existing surface could host it.** Extending a research command would break its own
test-pinned description (*"reads no business file, sends no internal data"*, on all four);
extending an analytics command would break the mirror (*"no external research"*). That is the
repository demonstrating that extension is architecturally inappropriate, which is what
justifies one new bounded surface — recorded as ADR-0029's Options A and B.

## 6. The seam

`commands.local_join()` — five functions in `commands/joins.py`, sequencing only.

```
commands.run(...)                      -> CommandResult (genuine AnalysisSet / KPIResult)
research.close_retrieval_object(...)   -> genuine EvidenceSet              (ADR-0024)
commands.local_join(...)               -> from_analysis_set / from_kpi_result
                                       -> synthesis.footed_statement()     (ADR-0028)
                                       -> one SynthesisSet(strict)
                                       -> synthesis.compare_values()
```

It computes no figure, authors no footing, resolves no dimension, compares nothing itself and
holds no privacy rule. What it adds is ordering plus refusals: a genuine `CommandResult`
(strict type check, status `ok`, not halted), a strict `SynthesisSet`, a named dataset for
ADR-0023 footing, and a deterministically selected internal metric — ambiguous or absent
metrics are refused rather than picked.

**The module is `joins.py`, not `local_join.py`.** `from .joins import local_join` binds the
function in the package namespace; had the module shared that name the function would have
shadowed it, and `biq.commands.local_join` would resolve to a callable rather than the
module. This was found by a test failing with `'function' object has no attribute
'internal_statements'`. `research/intents.py` holding `intent()` is the same convention.

## 7. One additive change to an approved translator

`from_kpi_result()` gained `metric_definition`, `geography`, `scope` and `methodology` —
**mirroring `from_analysis_set()`, which already had exactly those four**. All default to
`None`, so every existing caller's output is byte-identical; M10.1's 126 synthesis tests pass
unmodified.

The asymmetry was an accident of sequencing: M10.1 predates the dimension architecture that
arrived at R.6. Its effect was that a KPI-based comparison could reach at most three of seven
dimensions and could never be compatible, which would have made scope item 9-B undeliverable.
`merge.py` is not a protected component, the change adds no mechanism and re-judges nothing,
and it is recorded in ADR-0029.

## 8. A wrong approach, found and removed

The first implementation set the missing KPI dimensions with `setattr()` **after**
`from_kpi_result()` had already added the item to the set. It silently did nothing: `add()`
computes `_resolved_dimensions` during resolution, and `dimensions` reads that snapshot, so a
later attribute write is invisible to the comparison. The test caught it as
`'unknown' != 'compatible'`.

It was the wrong shape as well as wrong in effect — mutating an already-resolved item is
exactly the after-the-fact edit this architecture refuses everywhere else. The fix was to
pass the dimensions *into* construction, which is what §7 enables.

## 9. Internal data stays local

Two independent guarantees, and the first is the one that matters.

**Structural.** The seam imports no gate, no query builder and no retrieval request. It
*cannot* construct or alter an outbound query even if instructed to. A test scans the
module's **code** — docstrings stripped, because a paragraph explaining "this imports no
gate" would otherwise fail a test asserting the word's absence — for `gate_mod`,
`gate.assess`, `open_retrieval`, `close_retrieval`, `public_terms`, `CandidateQuery`,
`RetrievalRequest`, `ScoutBrief`, `query_text`, `DisclosureDecision`, `urllib`, `socket` and
`http`. It receives a retrieval that has **already closed**, so the external request was
built, gated, dispatched and normalised before any internal figure was in scope.

**Empirical.** The sentinel is the real figure from the real run — `3467850.16`, not an
invented constant — and it is absent from the query text, the scout brief, the ledger entry,
the retrieval brief, the evidence content and the serialised evidence set. So are its whole,
truncated, comma-formatted and two rounded forms, and every row-level demo token
(`northwind`, `fenwick`, `marchmont`, `delacroix`, `okafor`, `so-41011`, `.csv`, `.xlsx`).
A blocked, insufficient, unauthorised or zero-record retrieval raises rather than joining,
and the sentinel appears in none of those results — there is no fallback in which anything
internal is sent.

## 10. A pre-existing gate limitation, found and reported

Writing the privacy tests surfaced a property of the **disclosure gate**, not of the join.

The gate refuses terms by **key name** against the list in `research.contract`. It correctly
refuses `rows`, `customers`, `transactions` and `ledger`. A caller that labels an internal
figure with a key *not* on that list — `our_revenue` — is **authorised**, and the value
lands verbatim in the outgoing query text.

This is a pre-existing M9-A property. The local join neither introduces it nor can fix it:
the seam builds no query at all. It is **not** fixed here, because the disclosure gate is an
approved security contract and changing it is its own milestone with its own ADR.

What was done instead: a test pins the behaviour so it cannot change silently, names it as a
gate limitation rather than a seam one, and asserts the two controls that do cover it today —
the seam's structural inability to transmit, and the explicit prohibitions in both the skill
(*"the internal figure is never part of the question you ask… not rounded, not banded, not as
a range"*) and the command (*"the internal figure is never part of the query"*). It is
recorded in ADR-0029's Consequences and flagged for a future milestone.

## 11. The user-reachable surface

`/benchmark-comparison` (thin orchestrator) and `biq-benchmark-comparison` (judgement and
workflow), following the four research pairs exactly. No new intent: `BENCHMARK` already
exists and is category-agnostic by design.

The command carries no implementation machinery — asserted by test for `open_retrieval(`,
`close_retrieval(`, `python -c`, `WebSearch`, `WebFetch`, `Task(`, `EvidenceSet`,
`evidence_id`, `BIQ-REC/1`, `source_tier`, `DimensionProvenance` and `from_analysis_set` —
and carries no registry spec, because it drives no single pipeline: it names a metric and the
skill invokes whichever analysis command computes it.

The skill's three rules are the ones that keep the surface honest: the internal figure is
never part of the question; the skill compares and does not judge; and two figures are not
comparable until the engine says so. It also states plainly that *"a benchmark that was
chosen to sit near our number is not a benchmark, it is a mirror."*

## 16. Issues discovered

**Four of my own defects, each found by a test and fixed rather than worked around.**

1. **Module/function name shadowing** (§6) — `local_join.py` defining `local_join()` made the
   function shadow the module in the package namespace. Renamed to `joins.py`.
2. **`cls.run` shadowed `TestCase.run()`**, so unittest tried to call a `CommandResult`.
   Renamed to `cls.command_run`.
3. **`setattr` after `add()`** (§8) — silently ineffective, and the wrong shape.
4. **A self-referential source scan** — the seam's docstring explains that it imports no
   gate, which failed a test asserting the word `gate` is absent from the module. The scan now
   strips docstrings and comments and reads the code.

**One test module was too slow** — 104 tests each re-running the full pipeline over 2,204
rows exceeded a two-minute timeout. The run is deterministic, so it is computed once and
shared; the two tests that *mutate* a result take a fresh one. 25s.

**One genuine pre-existing finding** — the gate's key-name basis (§10).

## 19. Remaining limitations

1. **A percentage metric cannot reach `compatible`.** `currency` is unstated on both sides of
   a margin comparison and `compare()` treats unstated as `unknown`. Architecture.md's own
   headline example returns `unknown` on `currency`. Closing it means changing compatibility
   semantics, which is protected.
2. **The gate refuses terms by key name** (§10). Pre-existing, not introduced here, not
   fixable from the seam, and its own milestone.
3. **The internal dimensions are the caller's description of its own data.** The engine can
   refuse a comparison but cannot check that *"whole business, all segments"* truthfully
   describes the file — the internal mirror of ADR-0026's containment-is-not-meaning.
4. **One metric against one benchmark.** The surface compares a single pair by design;
   multi-metric comparison would be a different shape.
5. **Strictness is a call-time refusal**, not a property of the type, because the seam accepts
   a caller-supplied set so both halves can share one.
6. **Nothing is verified live.** Every fixture is synthetic and in-memory; the internal side
   is the shipped synthetic demo file.
