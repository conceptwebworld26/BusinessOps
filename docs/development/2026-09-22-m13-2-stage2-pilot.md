## 10. Issues discovered

**1. M13-DEF-06 — a refused run was scored as a pass.** Recorded in `docs/testing/defects.md`. The part that is
ours to fix: no repository guard rejects a platform result whose run did not execute. The remediation is a
recording rule — a result is admissible only if its run took a turn and carries no error — enforced by the
validator. Not fixed here; this task was authorised for one run and nothing else.

**2. The environment condition, which is larger than this case.** Every one of the 64 cases declares
`tool_grants: engine-python`, which becomes a `Bash` grant. On a machine with **no active sandbox backend the
harness refuses the run rather than running it unconfined** — a deliberate, correct safety choice on its part. So
**no case in this suite can execute in this environment**, and that is not a property of `a01`.

ADR-0040 §2 is explicit that environment-unavailability is **never** given an `M13-DEF-NN` id: it is an owner
decision. The options, none of which I may take unilaterally:

- run the suite on Linux or macOS with the sandbox backend installed;
- enable the Windows sandbox feature gate on this machine, if that is available to the owner;
- accept the gap under ADR-0040 §2, with its five eligibility conditions tested and an owner date;
- change what the cases grant — but `engine-python` exists because the engine's determinism (ADR-0002, ADR-0042)
  is the behaviour under test, so dropping it would hollow out the suite rather than fix it.

**3. Two of the four pilot objectives are unresolved**, and neither is guessed:

- **The trace tool name for a plugin slash command: unresolved.** The trace contains no tool event at all, because
  no turn ran. Nothing was inferred from symbols, function names or naming similarity. The 24 pending graders
  therefore stay pending, untouched.
- **Sandbox input delivery: unresolved.** The sandbox's `home/cwd/` was empty when the run was refused, but the
  refusal preceded any turn, so this says nothing about how an input would have been delivered. It is not evidence
  either way.

## 11. Decisions made

No ADR. One judgement, stated plainly: **a reported pass from a run that never executed is not a pass.** The
alternative — recording `automated_pass` for `a01` because the JSON says `passed: true` — would have been the first
false green in this repository's evidence model, in an approval case, which is the worst place for one.
