# Coverage matrix — Milestone 13

Defined by [ADR-0039](../decisions/ADR-0039-m13-test-hardening-and-evals-contract.md) §B, as amended for `gap` by
[ADR-0040](../decisions/ADR-0040-m13-owner-accepted-environment-gap.md). Every row comes from one of
seven closed, in-repository enumerations. `tests/unit/test_m13_coverage_matrix.py` validates this file on every run:
set sizes against their sources, the closed status and evidence vocabularies, and that every cited test exists.

> **ADR-0007's "24 specified scenarios" are unavailable.** They lived in a product specification that was never
> committed. They are **not reconstructed** (ADR-0039 I-12). No row below claims to correspond to one of them, and
> whatever that list held beyond these seven sets is unknown and uncovered.

**Columns**

- **Layer:** `deterministic`, `behavioural` or `manual`.
- **Covering tests:** `sub.module.Class.test`, as `python tests/run_tests.py -v` names them. Behavioural rows name
  their M13.2 eval case files, `evals/<suite>/<case>/case.yaml` ([eval-suite.md](eval-suite.md)). A deterministic row
  whose requirement also has a behavioural half names that case in its notes. A case file is a specification; it is
  not a covering test and not evidence.
- **Status** (exactly one):
  - `covered` — a named test covers the requirement and ran, not skipped, in the M13.1 closing run;
  - `covered-by-M13` — the same, where M13.1 added the test;
  - `behavioural-only` — no deterministic statement is possible;
  - `not-applicable` — with the reason;
  - `gap` — with the id that explains why it is still open. That is either the §G.1 defect id or, for an
    owner-accepted environment-unavailable gap, the complete ADR-0040 §3 disposition record under its owner-decision
    id. S2-14 is the only such row (U-1; see *S2-14* below). It is never a defect id, and never coverage.
- **Evidence:**
  - behavioural rows carry one ADR-0039 §E.6 class (`automated_pass`, `automated_fail`, `not_executed`,
    `execution_unavailable`), plus any `manual_observation`;
  - deterministic rows carry `deterministic` when their tests ran;
  - a deterministic row whose tests could not run carries `execution_unavailable`.

**M13.1 state.** No eval case existed, and every behavioural row was `not_executed`.

## S2-14 — open gap, environment unavailable (U-1)

**Owner decision, 2026-09-18: U-1 (c), accept S2-14 as an open gap.** The row is recorded as it stands, and nothing
was done to make it look covered. It is the first application of

**Disposition record** (ADR-0040 §3; every field is mandatory):

| Status | `gap` |

| Reason execution is unavailable | The system interpreter, Python 3.13.1, cannot import openpyxl, so all eight Tier-1 equivalence tests are skipped. `CLAUDE.md` §4 and ADR-0008 prohibit installing openpyxl there. **Supporting detail.**

- **Why the Tier-1 tests cannot run.** Tier 1 is openpyxl importable in the interpreter that runs the suite
  (`lib/python/bops/runtime/tiers.py`, `TIER_OPENPYXL_SYSTEM`). The mandated system Python, 3.13.1, cannot import it
  (`ModuleNotFoundError: No module named 'openpyxl'`). Every Tier-1 comparison is therefore
  `skipUnless(openpyxl_available())`: 7 tests in `integration.test_data_layer.TestCrossTierEquivalence` and 1,
  `integration.test_vertical_slice.TestCrossTierEquivalence.test_tier1_and_tier3_agree`.
- **Why openpyxl cannot be installed there.** `CLAUDE.md` §4 and ADR-0008 allow openpyxl only in the consented,
  isolated runtime under `~/.claude/businessops/runtime/`, "never into the system or project interpreter". That
  managed install is Tier 2, a separate process, so it would not un-skip these Tier-1 tests either.
- **What is claimed.** Nothing about equivalence. No test was weakened or replaced, no synthetic stand-in was added,
  and no environment was fabricated. The Tier-3-versus-CSV test that does run is not evidence of Tier-1 equivalence.
- **What it is not.** It is not a product defect and not an M13 infrastructure defect, so it has no §G.1 record. The
  skip is correct: the tests are right to refuse to compare against a reader that is absent.
- **How it could close.** A future run under an owner-approved environment in which Tier 1 is available could execute
  the eight tests. That run would have to be recorded before the row could change. Until then S2-14 stays `gap`.

**ADR-0039 conformance.** ADR-0039 as accepted required every deterministic `gap` to carry a §G.1 defect id, and
S2-14 honestly has none. ADR-0040 amends only ADR-0039 §B's `gap` definition and §L's second M13.1 condition, to
admit a gap with the complete disposition record above. With that record, S2-14 meets the amended §L. It stays a
`gap`: the amendment records the gap, and it does not make the row covered. An owner decision cannot turn
unavailable evidence into positive evidence (ADR-0040 §4).
